# dsh-echo-memory · 回响记忆

给 DeepSeek Harness 的长期记忆，**情绪越强，忘得越慢**。

> 改编自 [MingHuanYue/dsh-tide-memory](https://github.com/MingHuanYue/dsh-tide-memory)（MIT）。
> 上游把「带情绪的事淡得更快」写成了设计（事件半衰期 30 天、带情绪 7 天）；
> 本版把这条反过来，并把「情绪」从一个布尔开关改成连续变量。改动清单见 [NOTICE](./NOTICE)。

---

## 它解决的问题

普通的 AI 记忆是「存下来 + 全塞回去」：要么每轮被淹，要么漏掉真正要紧的。
真正的难点从来不是存储，是**哪些能进上下文、按什么顺序排**。

回响记忆的两段式：

| 决策 | 谁说了算 | 默认 |
|---|---|---|
| **能不能进上下文** | 证据分 `C` | `C < 0.35` 根本不进，宁可少想 |
| **排多靠前** | 排序分 `P`（含鲜活度、重要度、情绪） | 最多 6 条 / 800 字 |

关键性质：`P = C × (...)`，括号里系数合计 1.0，所以 **`P ≤ C`** ——
排序永远无法伪造出「证据」。一条不相关的旧事不会因为新、因为重要、因为情绪浓就混进来。

## 情绪怎么进入遗忘曲线

```
halfLife = base × (1 + span × emo^gamma)

base  = 事件基线半衰期（默认 30 天）
span  = 情绪增益（默认 2 → emo=1 时半衰期为 3 倍）
gamma = 曲线形状（默认 0.7 → 「有点情绪」就开始明显减速）
emo   = 0~1，模型写记忆时自己打的情绪强度
```

`act = 0.5 ^ (days / halfLife)`，`days` 从**最后一次被写入或被想起来**算，
所以反复被想起的记忆会回血。

对照表（base = 30 天）：

| 情绪 emo | 半衰期 | 30 天后留存 | 90 天后留存 |
|---:|---:|---:|---:|
| 0（平铺直叙） | 30.0 天 | 50.0% | 12.5% |
| 0.3 | 55.8 天 | 68.9% | 32.7% |
| 0.5 | 66.9 天 | 73.3% | 39.4% |
| 0.8 | 81.3 天 | 77.4% | 46.4% |
| 1（极强烈） | 90.0 天 | 79.4% | 50.0% |

（表由 `node -e` 直接调用 `lib/decay.js` 算出，不是估算。）

一句话：**「那天吃的抹茶小蛋糕」比「今天开了个会」多记三倍久。**

### 为什么要 `emo^gamma` 而不是直接线性

γ=1 时 0.5 和 0.9 只差 1.8 倍，区分度不够。γ<1 把曲线往上抬，
让中等唤醒度就已经明显减速 —— 这更接近遗忘曲线的实际形状。
调 γ 是这套东西最有效的一个旋钮。

### 为什么封顶 3 倍

超过 3~4 倍后记忆实际已经「永久」了，再长没有语义差别，
但会让高情绪条目永远压在别人头上，把记忆库变成只进不出的排行榜。

### 归档层的配套改动

上游的冷宫条件是 `act < 0.05 && hits === 0`。
如果只改衰减不改归档，会出现**两头打架**：算法说这条能留 90 天，
归档逻辑第 60 天就把它扫走了。所以本版加了情绪豁免 ——
`emo ≥ 0.6`（可调）的条目即使淡透了也不进冷宫。
「淡忘」是降低浮现优先级，不是删除；冷宫也不删除，可翻回来。

## 工具

四个工具，模型自己会调：

| 工具 | 作用 |
|---|---|
| `echo_remember` | 记一条：`text` / `kind`(event\|fact) / `importance` / `emotion` / `tags` / `supersedes` |
| `echo_recall` | 按线索翻：`query` / `limit`，返回带鲜活度与情绪的条目 |
| `echo_forget` | 真删（想保留历史用「标过时」） |
| `echo_stats` | 看库里多少条、最鲜活的是哪几条 |

`emotion` 是这个插件最关键的参数，工具描述里已经明确告诉模型怎么用：

> 开心、难过、生气、感动、意外的时刻给 0.6~1，平淡的交代给 0~0.2。
> 情绪越高忘得越慢（emo=1 时能比基线多活两倍）。

### 另外两个机制（沿用上游）

- **取代而非删除**：新版本事实进来时填 `supersedes`，旧的不删、标 `supersededBy`，留链可回看。
- **冲突摊开**：同类型记忆撞了关键词会记冲突，注入时把「两条对不上」并排说清楚，不替模型判断谁对。

## 设置页

`设置 → 回响记忆`，最上面是一张**遗忘曲线图**：四条线分别是情绪 0 / 0.3 / 0.6 / 1，
横轴天数、纵轴留存率，红色虚线是归档线。改参数曲线立刻重画——
不用你自己心算 `span=2 gamma=0.7` 是什么意思。

每条记忆显示：

```
半衰期 92 天（基线 30 × 情绪 3.07）· 已过 12 天 · 再过约 140 天淡到底
```

可调旋钮：事件基线半衰期、情绪增益、曲线形状、情绪归档护栏、
每轮条数、证据阈值、字数上限。

### 给老记忆补情绪

升级前存的记忆 `emo` 全是 0，吃不到新算法。设置页有个「给老记忆补情绪」按钮：

1. 先点一次 → 出**提案列表**（`0 → 0.55 · 命中了 1 个强情绪词 · 那天真的特别感动`），**不写盘**
2. 看一眼没问题，再点「确认写入」

刻意分两步：情绪是主观强度，让用户先看清它打算怎么改，比闷头改完再解释强。

推断只用两个可解释的信号（重要度 + 情绪词命中），且：

- **只提升不降低**——已经标了更高情绪的条目不动
- **封顶 0.85**——「100% 强情绪」这种判断只有当事人能给
- 没信号的直接跳过，不瞎猜
- 改动写进 `trace.jsonl`，可回看

## 安装

```bash
dsh plugin --profile desktop add file:/path/to/dsh-emotion-memory
# 或从本地源码目录
dsh plugin --profile desktop add file:C:/Users/86185/Desktop/code/DSH/dsh-emotion-memory
```

装完重启一次 DSH。

## 数据在哪

```
$DSH_HOME/echo-memory/
├── config.json          # 设置
├── trace.jsonl          # 注入日志（每轮注入了哪几句、C/P/act 各是多少）
├── pulse.json           # 今天翻了几次、用上几次
├── echo.log             # 诊断日志（挂载失败会写这里）
├── stores/<key>.jsonl   # 每个工作区一个库
└── cold/<key>.jsonl     # 冷宫：淡到底又没被想起的（没删，能翻回来）
```

纯 JSONL，`grep` 就能翻，也能自己写脚本搬进搬出。按**工作区**分桶，换项目不串味。

## 权限与隐私

- 只读写 `$DSH_HOME/echo-memory/` 下自己的文件，不碰别的目录。
- **不联网**：没有云端、没有 embedding、没有 key。分词和检索全在本地算。
- 记忆只有两个来源：模型主动调 `echo_remember`，或你在设置页手动记一条。
- 卸载插件不会删数据，重装还在。

## 兼容性

- DSH >= 0.1.7-rc.1（实测 0.2.1-rc.2），Node >= 22。
- 桌面端和 web 端都能用（client 走 `dsh.client`，platform: web）。
